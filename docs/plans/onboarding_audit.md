# Onboarding audit: what the player is told, and whether it is true

Companion to [onboarding.md](onboarding.md) (its principles 0 and 7). Made 2026-11-13 against the code at
that date. Two halves:

- **The cards**: every tutorial card and hint, read off the code by `scripts/tutorial_audit.py` (rerun it and
  diff the table to see what changed).
- **The rules**: every rule the game runs, in four areas, read from the code and `locales/en.json`: where the
  player is told it, whether the numbers are right, and where it can be read again after the moment has
  passed. The four area tables were drafted by reading the code module by module; the findings marked
  *checked* below were confirmed by hand against the code. A row not marked is a lead to confirm when it
  is acted on, not a fact.

"Read again later" is the column the author asked for: a screen card is safe (its `?` reopens it forever), a
hover or a wiki entry is safe, a one-time hint is not.

## What to fix first

### 1. Text that says something the code does not do

These are wrong today, whatever the onboarding becomes. Every row *checked* by hand against the code and
the locale key's path.

| Text (locale key) | Says | The code does |
|---|---|---|
| ui.talents.racial_next, ui.talents.head.racial, ui.report.gain.racial.why | every level in any track adds a hit die | two levels add one: the racial curve is 2n (`progression.RACIAL_XP_THRESHOLDS`) |
| ui.map.food, ui.craft.food, ui.shop.till_note, guild_upkeep.no_food_left_whole_guild | people eat, and the till refills, "at dawn" | daily upkeep (meals, rot, refills) runs at midnight (`guild_upkeep.py`, `pass_time`). Fixed: the texts now say midnight |
| wiki_rules.money.3 | hunger brings sickness | only Rotten Food makes a character sick |
| item.tip.food | a ration prevents starvation "when resting" | a ration is eaten every midnight, resting or not |
| action.first_aid.desc | 100% chance to stabilize | d20 + Wisdom against 10 (`data.FIRST_AID_DC`) |
| tutorial.hint.fallen | Stabilize is a Wisdom check | a flat d20 against 11 (`data.DEATH_SAVE_MIN`); the action's own "50%" is right |
| tutorial.battle | L shows the whole squad's sight | the web client has no L key (it was the pygame screen's) |
| action.demoralize.desc | the target cannot move | no movement rule: -1 to attack, AC and MD per stack, up to 3 |
| guild_sheet.adds_cha_bonus_to_taverna | the leader adds a CHA bonus to recruiting | every member adds their own CHA; the leader adds their racial level on top (`recruit.LEADER_SPONSOR_TERMS`) |

One more is an omission, not a contradiction: ui.guild.fame_foot says fame "is how many bands the guild can
keep on the road at once" and never mentions that it also sets the routine seats
(`routine_book.FAME_PER_SLOT`). Fame is never spent, so "never buys anything" is true.

More, smaller ones (the shop's resale percentage, the Medic's poison time, the morale wiki line, the stance
tooltip, a missing -4 in the hunger wiki line) are in each area's "Wrong or contradicting text" list below.

The "dawn" one was a design call. Author, 2026-11-13: people eat at midnight, as the code does, so the
text was wrong. The meal texts now say midnight (ui.craft.food, ui.craft.food_days, ui.map.dawns,
guild_upkeep.no_food_left_whole_guild, in English and pt-br), and so do the shop's till note and the
Treefolk's bloom, which run in the same midnight upkeep. The author's rule for this one: between
midnight and dawn, the code is right. "Come back at dawn" (light) stays: the day lightens at 06:00.

The rest of this table is the author's to go through row by row: each one is either a wrong text or a
wrong rule, and only the author can say which.

### 2. Rules the player is never told (leads, to confirm when acted on)

The ones that shape a first week, from the four area tables. These were not each confirmed by hand; a
row is confirmed when its note or hint is built. One known nuance: the Old Road's ambush chance is the
same constant the watch card fills (`world.ROAD_AMBUSH_CHANCE`), but that card speaks of a wagon left
outside the Ruins, not of the road, so the road itself still says nothing.

- **Body:** how fast rest heals and that it ticks every 8 hours; what sickness costs and when it passes; the
  -2 Strength and Dexterity of carrying too much; the Old Road's 20% ambush chance per leg; what night does
  to an outdoor fight; that a death by starvation or collapse loses the gear.
- **Money and work:** the wage itself ($1 per 4-hour block, more with the right tool, more at the Mine);
  how work XP is earned; that combat XP is kept only by the survivors; how haggling and the shop's till
  work; how a recipe's level is set; that a failed job comes back after a week or two.
- **People and world:** a member's crime record and what raises it; the guard's odds and the days in the
  cells, before the choice; the Champion of the Pit's cycle; the daily cohesion roll and the cost of too
  many bands; that danger by place (jurisdiction) has no lasting entry.
- **The fight:** how initiative is rolled; terrain, shallow and deep water, falling and fire damage; the -4
  to hit what the dark hides; Demoralize's range, shared language and cap; Flee dragging a fallen ally;
  the end-of-fight death save, and that a lost fight kills everyone down; the Tab key and how the 1-8
  hotkeys shift.

### 3. What cannot be read again

- **All 8 hints.** Once closed, a hint is never shown again; its "See in the wiki" is the only way back, and
  it lives inside the hint. *Checked*: the map's and the battle's `tutorial_key` stop returning a hint once
  it is seen, so the `?` reopens the screen's card instead.
- **The danger hint has no wiki entry at all** (`hints.wiki_ref` has no row for it). *Checked.*
- **The wiki's Rules chapter has 17 sections**, and none for: rest and healing, light, carry weight, travel
  stance, the Old Road, wages, XP and levels, haggling, missions, crafting, the Arena, crime, the
  Champion, cohesion. For these the only lasting text is a screen card behind its `?`, or nothing.

### 4. Hovering a foe's action in the battle chronicle

Not possible today (*checked* by the combat area): the chronicle's lines reach the client as plain text, so
the action's id is lost. The fix is to send the action's id with the line and wrap its name in the client
with the same hover the wiki uses (`wiki_terms.tip`). Also: the action plate on hover shows the action's
label, never its description.

### 5. The cards themselves

From the cards table below: 52 cards and 4,193 words. One card is never shown (the combat lab card: no
screen returns it). Two cards are shown but missing from the `TUTORIALS` list (work, ox_hunt), so whatever
reads that list does not see them. A few cards type a number instead of filling it from the code (3d6,
1d20 + INT, "three" for the team size): right today, but they would not follow a change.

## Wrong or contradicting text

- `ui.talents.racial_next` ("next racial pick at racial level {n} · every level anywhere adds a hit die"): code gives one hit die per RACIAL level and the racial curve is 2n (`progression.py:67`), so two levels anywhere (combat + work + magic summed) make one hit die; a character at combat 1 has racial 0 and no new die. Verified: racial levels at sums 0..6 are 0,0,1,1,2,2,3.
- `ui.talents.head.racial` ("it climbs with every level in the other three, a hit die each"): same error.
- `ui.report.gain.racial.why` ("one level of each track is one of the race's"): garbled; the true rule is two track levels per racial level.
- `guild_sheet.racial_xp_is_sum_of` ("Racial XP is the sum of combat and work levels"): `unit_levels.py:46` sums combat + work + magic.
- `trade.you_sell_at_of_price` (the deal card's "you sell at 50% of the price", `trade.py:143`): always the fixed `SELL_FACTOR`; the real resale is `base x (0.5 + 0.4 x deal)` per item (`economy.py:454`), so with a good haggle (deal up to +25%) it is up to 60%, with a bad one as low as 44%. The card contradicts the prices shown beside it.
- `ui.shop.till_note` ("refills at dawn"): the till gains only $25 a day up to $500 (`economy.py:246-253`), it does not refill whole.

### Wrong or contradicting text

- `action.demoralize.desc` ("Cha vs MD. Target is demoralized (cannot move, lower defenses)"): the code (`conditions.py:49-71`) has no movement restriction. The real effect is -1 attack, AC and MD per stack (max 3), one stack lost at the end of its turn. `ui.cond.demoralized.rule` ("-1 ... until the end of its turn") is right only for a single stack; it hides the stacking.
- `action.first_aid.desc` ("100% chance to stabilize"): code rolls d20 + WIS vs `FIRST_AID_DC`=10 (`support.py:230`), so it can fail and the charge is spent either way.
- `tutorial.hint.fallen` body line 2 ("Stabilize ... a Wisdom check ... First Aid does it better with the right kit"): `Stabilize._attempt` is a flat d20 >= 11 (`support.py:176-177`), no Wisdom. First Aid is d20 + WIS vs 10, so "better" depends on the Wisdom modifier.
- `tutorial.battle.body[1]` ("L shows the whole squad's sight"): the web client never sends `view_squad` (`battle_session.py:517` passes False and `battle.js` has no `L` handler); the key exists only in the pygame editor. The sentence promises a control that does not exist.
- `wiki_rules.morale.4` ("Nothing else raises it yet"): Inspiring Shout calls `morale.lift` (`combat.py:357-376` (_inspire), a rally of morale on the weakest ally) and Dread Voice changes the fall of a Demoralize, so morale does have other sources. (talent texts are `desc.talent.inspiring_shout`.)
- `Flee` docstring (`combat.py:433-436`, "downed allies are left behind") vs `combat.py:505-509` (an adjacent downed ally is dragged out with you): code comment only, but the player text is silent, so a player cannot know either.
- `wiki_rules.turns.5` renders "Delay (0 points)" while the battle card shows "Free": not a contradiction, but two wordings for one fact.
- `action.assess.desc` "once per foe each round" is per SIDE in the code (`intel.py:211`, key `(actor.team, target)`): after one character assesses a foe, no teammate can that round.

### Chronicle hover

No. `renderLog()` (`gartok/web/client/screens/battle/battle.js:352-366`) builds each line as a plain `<p>` from `Dice.inkLine(esc(line))` and only wraps unit names in a coloured `<span>`; no `data-tip` is attached. The log arrives as plain strings (`battle_session.py:603` `list(b.log_lines[-LOG_LINES:])`), so any `Ref` (kind, id) in a line is already flattened to text by `Ref.__str__` (`i18n.py:259`), and the action name is not even a Ref in most templates (`log.attack.head`, ...). To make an action name hoverable: have the log lines carry the action id (a `Ref("action", id)` kept through serialization, or a marked span in the string), and wrap it in the client as `data-tip` filled from `wiki_terms.tip(id)` (`wiki_terms.py`, the same text the wiki shows), which the existing `Tip` (`kit.js:107`) will render.
